# AI Manifest - База знаний проекта

Данный документ описывает структуру базы знаний проекта в Obsidian для AI-агентов и разработчиков.

## Назначение

Папка `/docs` - это база знаний проекта, где каждая фича представляет собой **модуль/феномен/смысл/слой/сервис** проекта. Это не классический бэклог менеджмента, а структурированное описание архитектуры и механик проекта для понимания AI.

## Структура базы знаний

### Папка `/docs`
Obsidian хранилище с возможностями:
- **Граф связей** - визуализация архитектуры проекта
- **Обратные ссылки** - отслеживание зависимостей
- **Теги** - категоризация по доменам и типам
- **Поиск** - глобальный поиск по всей базе знаний

### Папка `/backlog`
Содержит описания фич проекта в плоской структуре для максимальной масштабируемости.

## Принципы организации

1. **Плоская структура** - все фичи в одной папке
2. **Метаданные-управляемая** - фильтрация через YAML frontmatter
3. **Тег-ориентированная** - группировка через теги
4. **Связно-центричная** - связи важнее иерархии папок

## Структура фичи

Каждая фича должна содержать:

### 1. Метаданные (YAML frontmatter)
```yaml
---
title: "Название фичи"
status: "active|archived"
domain: "auth|api|ui|infra|data|business"
dependencies: ["фича-1", "фича-2"]
tags: ["type/feature", "domain/auth", "tech/backend"]
epic: "user-management"
created: 2024-01-01
updated: 2024-01-15
---
```

### 2. Описание фичи
Подробное описание назначения, функциональности и бизнес-логики.

### 3. Документация фичи
- Технические детали
- Архитектурные решения
- API документация
- Схемы и диаграммы

### 4. Критерии понимания
Чеклист для проверки понимания фичи:
```markdown
- [ ] Понимаю назначение фичи
- [ ] Понимаю техническую реализацию
- [ ] Понимаю связи с другими фичами
- [ ] Могу объяснить бизнес-логику
```

## Организация знаний

### Домены
- `auth` - аутентификация и авторизация
- `api` - API endpoints и интеграции
- `ui` - пользовательский интерфейс
- `infra` - инфраструктура и DevOps
- `data` - работа с данными
- `business` - бизнес-логика

### Теги
```yaml
tags: 
  - "type/feature"        # тип документа
  - "domain/auth"         # домен
  - "tech/backend"        # технология
  - "status/active"       # статус
```

### Эпики
Группировка связанных фич:
```yaml
epic: "user-management"
epic: "api-v2"
epic: "performance-optimization"
```

## Рабочий процесс для AI

1. **Анализ проекта**: Изучите существующий код и структуру
2. **Выявление фич**: Определите модули/сервисы/функциональности
3. **Создание описаний**: Создайте файлы фич в `/backlog/`
4. **Установка связей**: Свяжите фичи через зависимости
5. **Детализация**: Заполните все разделы для каждой фичи
6. **Категоризация**: Установите теги, домены и эпики

## Навигация в Obsidian

### Связи между фичами
- `[[название-фичи]]` - внутренние ссылки
- Двусторонние связи для отслеживания зависимостей
- Теги для группировки

### Поиск и фильтрация
```
# Поиск по домену
tag:#domain/auth

# Поиск по эпику
epic: "user-management"

# Поиск по технологии
tag:#tech/backend
```

### Полезные команды
- `Ctrl+Shift+F` - глобальный поиск
- `Ctrl+G` - граф связей
- `Ctrl+Shift+E` - обратные ссылки

## Структура файлов

```
backlog/
├── README.md                    # Инструкции по работе
├── dashboard.md                 # Автоматические отчёты
├── templates/
│   └── feature-template.md      # Шаблон для новых фич
└── [фичи проекта...]           # Описания фич
```

## Преимущества

1. **Масштабируемость** - легко добавлять новые фичи
2. **Гибкость** - фильтрация по любым критериям
3. **Связность** - визуализация архитектуры в графе
4. **Автоматизация** - динамические отчёты через Dataview
5. **Понимание** - структурированная база знаний для AI

Эта структура создаёт эффективную базу знаний для понимания архитектуры и механик проекта.
