Проект представляет собой разработку или доработку веб\-сайта (раздела существующего сайта) для турагентства "Азимут-тур", специализирующегося на речных (и потенциально морских) круизах. Платформа – OctoberCMS. Цель – создать современный, удобный и авторитетный онлайн-магазин круизов, улучшить пользовательский опыт, автоматизировать сбор отзывов и эффективно управлять контентом (круизы, теплоходы, скидки, условия).

Структурированный Анализ ТЗ:

### **1\. Бэклог Фич (Feature Backlog)**

Разделим фичи по основным модулям/областям. Статус указан согласно ТЗ.

### **2\. База Сущностей (Entities)**

* Cruise (Круиз):
  * Атрибуты: ID, Название (внутреннее), Маршрут (список городов/портов), Даты/Время начала и конца, Продолжительность (дни), Статус (активен/неактивен), ID Теплохода, ID Круизной Компании (через теплоход), Цена (базовая, тарифы), Наличие мест (статус/кол-во), Источник данных.
* Ship (Теплоход):
  * Атрибуты: ID, Название, Проект, Уровень/Класс, Кол-во палуб, Год постройки, Год модернизации, Длина, Ширина, Пассажировместимость, Описание, Фотогалерея, Ссылки на Видео (Youtube), ID Круизной Компании, Источник данных, Служебная информация.
* Cabin Category (Категория Каюты):
  * Атрибуты: ID, ID Теплохода, Название, Палуба, Вместимость (текст, число?), Комфорт (текст), Расположение кроватей (текст), Оснащение (окно/балкон/иллюминатор), Описание, Фотогалерея.
* Cabin (Каюта):
  * Атрибуты: ID, ID Теплохода, Номер каюты, ID Категории Каюты, Палуба, Координаты на схеме (x, y), Дополнительная информация (текст, статус отображения).
* Cruise Company (Круизная Компания):
  * Атрибуты: ID, Название, Логотип, Внутренняя информация.
* Port (Порт/Причал):
  * Атрибуты: ID, Город, Адрес (текст).
* City (Город):
  * Атрибуты: ID, Название, Фотографии (аватар \+ доп.).
* Discount (Скидка):
  * Атрибуты: ID, Тип (РБ/Акция, Постоянная), Название (внутреннее/публичное), Описание (внутреннее/публичное), ID Категории Скидки, Размер (%/сумма/текст), Даты действия (для временных), Статус (активна/неактивна), Счетчик дней (вкл/выкл), Применяется к (заказ/место), Учтена в тарифе (да/нет), Суммируется (да/нет, список совместимых), Возрастные ограничения (от/до, условие возраста), Сфера применения (Теплоход(ы), Круиз(ы), Компания).
* Discount Category (Категория Скидки):
  * Атрибуты: ID, Название, Подзаголовок, Аватар (для баннера).
* Other Condition (Прочее Условие):
  * Атрибуты: ID, Название (публичное), Описание (внутреннее/публичное), Статус (активно/неактивно), Сфера применения (Теплоход(ы), Круиз(ы)).
* Inclusion Set ("В стоимость входит"):
  * Атрибуты: ID, Внутреннее имя, Внутренняя информация, Текст "Включено", Текст "Доп. оплата", Экскурсии включены (да/нет), Статус (активно/неактивно).
* Payment/Cancellation Policy (Условия оплаты/отмены):
  * Атрибуты: ID, Внутреннее имя, Текст условий, Статус (активно/неактивно).
* Review (Отзыв):
  * Атрибуты: ID, ID Теплохода, Имя автора, Дата поездки (месяц/год), Опыт автора (раз), Оценки (Каюта, Питание, Обслуживание, Экскурсии, Анимация, Теплоход, Отдых в целом, Работа Азимут), Текст отзыва, Фотографии, Дата публикации, Статус (на модерации/опубликован).
* Rating (Оценка \- часть отзыва):
  * Атрибуты: ID Отзыва, Категория оценки, Значение (1-5).
* Ship Service (Услуга Теплохода):
  * Атрибуты: ID, Название (админ/фронт), Описание, Фото, Иконка.
* Landing Page (Посадочная Страница):
  * Атрибуты: ID, URL, Тип (Из Порта, Из Порта в Город и т.д.), Заголовок H1, SEO-текст, Преднастройки виджета (Город(а), Теплоход(ы) и т.д.), Шаблон/Дизайн.
* User (Пользователь / Сессия):
  * Атрибуты: ID сессии/cookie, История просмотров (ссылки на Круизы/Запросы), Избранное (ссылки на Круизы). (Для отзывов/бронирования \- ФИО, Телефон, Email).
* Booking Request (Заявка на Бронирование):
  * Атрибуты: ID, ID Круиза, ID(ы) Кают(ы), Данные Заказчика (Имя, Телефон, Email, Комментарий), Дата/Время создания, Статус.
* Callback Request (Заявка на Подбор):
  * Атрибуты: ID, Данные из формы (Город, Даты, Дни, Взрослые, Дети, Телефон, Email), Дата/Время создания, Статус.
* Photo (Фотография):
  * Атрибуты: ID, URL файла, Подпись, Связанная сущность (Теплоход, Каюта, Город, Отзыв и т.д.).
* FAQ Item (Вопрос-Ответ):
  * Атрибуты: ID, Тема/Группа, Вопрос (заголовок), Ответ (текст), Статус (активен/неактивен).

### **3\. Связи между Сущностями (Relationships)**

* Cruise 1-to-1 Ship (Каждый круиз на одном теплоходе)
* Ship 1-to-many Cruise (У теплохода много круизов)
* Ship 1-to-many Cabin Category
* Cabin Category 1-to-many Cabin
* Ship 1-to-many Review
* Ship many-to-many Ship Service (Услуги могут быть на разных теплоходах)
* Cruise Company 1-to-many Ship
* Discount many-to-many Ship / Cruise / Cruise Company (Скидка может применяться ко многим сущностям)
* Discount many-to-one Discount Category
* Other Condition many-to-many Ship / Cruise
* Inclusion Set many-to-many Ship (Один набор услуг для многих теплоходов)
* Payment/Cancellation Policy many-to-many Ship
* Review many-to-one Ship
* Review 1-to-many Rating
* Review 1-to-many Photo
* Booking Request many-to-one Cruise
* Booking Request many-to-many Cabin (В одной заявке может быть несколько кают)
* Port many-to-one City
* Cruise many-to-many Port (Маршрут круиза)
* City 1-to-many Photo
* Landing Page relates to Search Criteria (Города, Теплоходы и т.д.)
* User Session 1-to-many History Item (Просмотренный круиз или запрос)
* User Session 1-to-many Favorite Item (Избранный круиз)

### **4\. Ключевые Тезисы и Решения**

* Платформа: OctoberCMS.
* Цель: Создание авторитетного онлайн-магазина круизов, повышение удобства и конверсии.
* Позиционирование: Отдельная тема/раздел сайта для круизов для фокуса на специализации. \[40\]
* Юзабилити: Значительное внимание уделено UI/UX, включая мобильную адаптацию, интерактивные элементы (схемы, галереи), понятную навигацию (новое меню, хлебные крошки, закреп-меню). Примеры взяты с конкурентов (Про-круиз, Инфофлот, Водоход, 1001тур, Tripadvisor).
* Централизация Управления: Перенос управления повторяющимися данными (Скидки, Условия, Входит в стоимость, Компании, Услуги) в отдельные справочники/разделы админки для упрощения менеджмента. \[90\], \[126\]
* Гибкость: Предусмотрена возможность создания кастомных фильтров в поиске, добавления "прочих условий", гибкая настройка скидок. \[165\], \[87\]
* Контент: Необходимость создания/обновления большого объема контента (описания, фото, иконки, условия, FAQ).
* Рефакторинг: Признание необходимости технических доработок парсеров и БД. \[281\]

### **6\. Анализ: Лишнее и Недостающее**

* Потенциально Лишнее / Усложняющее:
  * Сложность Скидок: Система скидок очень гибкая, но и сложная в реализации и администрировании (суммирование, условия, пересечения). Возможно, стоит начать с упрощенной версии.
  * Интерактивная схема на мобильных: Вывод и удобное использование сложной схемы теплохода на маленьком экране может быть проблематичным и дорогим в разработке. Требует тщательного проектирования и тестирования. \[229\]
  * Функция "Показать расположение каюты на палубе" в Карточке Теплохода: Отмечено как требующее обдумывания по трудозатратам. \[202\] Может быть избыточным.
  * Большое кол-во "Спец.фильтров": Требует продуманной админки и четкого понимания, какие именно фильтры нужны. \[165\]
* Потенциально Недостающее / Требующее Детализации:
  * Приоритеты: В ТЗ нет явной приоритезации для не внедренных фич.
  * Морские Круизы: Упоминаются в контексте главной страницы и меню, но нет детального ТЗ на их поиск, карточки, специфику. Если они в скоупе, нужна детализация.
  * Роли Пользователей и Права Доступа (Админка): Не описаны. Кто может управлять скидками, кто контентом, кто системными настройками?
  * Производительность: При таком объеме данных и фильтров (особенно с мультивыбором и сложными условиями) нужно уделить внимание оптимизации запросов к БД и скорости работы сайта.
  * Обработка Ошибок (Frontend/Backend): Как система информирует пользователя и администратора об ошибках (например, при бронировании, при работе с API)?
  * SEO-требования: Упоминаются SEO-меню и оптимизация ЛП, но нет детальных требований к мета-тегам, ЧПУ, sitemap, robots.txt и т.д.
  * Аналитика: Кроме упоминания Я.Метрики для формы, нет требований к отслеживанию других событий (клики по фильтрам, добавление в избранное, этапы бронирования).
